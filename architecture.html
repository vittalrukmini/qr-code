What the HTML fetches from each Drive folder
🖼
Photos
mimeType starts with image/
Any image file in the folder is automatically included as a gallery slide.

Name files 1.jpg, 2.jpg… to match caption numbers. Ordered by filename.
📝
Captions
filename = captions.txt
One caption per line in format 1|Caption text here.

The number matches the photo filename. Missing captions are silently skipped.
📖
Read More Panel
filename = readmore.txt
First line = panel title. Remaining lines = body paragraphs (blank line = new paragraph).

Shown in a slide-up panel when visitor taps "Read More".
🎵
Background Music
mimeType starts with audio/
Any .mp3 or .m4a file in the folder is streamed as background music.

Music button is hidden automatically if no audio file is present.
Build flow — how HTML files are produced
1
Edit build.js
Add a gallery entry with title, folderId, outputFile. Logo is shared across all galleries.
2
Run build
node build.js — produces one self-contained HTML per gallery. Logo baked as base64.
3
Push to GitHub
git push — all HTMLs live in the qr-code repo, served by GitHub Pages.
4
Generate QR
Paste the GitHub Pages URL into qr.io or qrcode-monkey.com. Download and print.
5
Update content
Upload/edit files in Drive anytime. Gallery updates instantly — no rebuild, no new QR code.
Security measures
✓ Secured
API Key — HTTP Referrer Restriction
Key only works when called from https://vittalrukmini.github.io/*.
Anyone who copies the key cannot use it from their own site or app.
✓ Secured
API Key — API Restriction
Key is restricted to Google Drive API only.
Cannot be used to access Maps, YouTube, Gmail, or any other Google service.
✓ Secured
Read-Only Access
The API key has no write scope. It can only list and read files.
No one can upload, delete, or modify Drive content via this key.
✓ By Design
Public Folders Only
Only Drive folders shared as "Anyone with the link can view" are used.
Private files in other folders remain completely inaccessible.
ℹ Note
Key Visible in HTML Source
Because this is a static site with no backend, the API key is visible in page source.
The referrer + API restrictions above make this safe — the key is worthless without the approved domain.
✓ No Backend
Zero Infrastructure
No server, no database, no credentials stored anywhere.
GitHub Pages is static hosting — nothing to compromise or maintain.
File naming rules — what to upload to each Drive folder
🖼
Photo files
Rule: name as 1.jpg, 2.jpg, 3.jpg…
Files are sorted by name — numeric naming ensures correct order.

The number becomes the caption lookup key. A photo named 3.jpg shows the caption from line 3|… in captions.txt.

Any image format works (.jpg, .jpeg, .png, .webp).
📝
captions.txt
Rule: exact filename captions.txt
One line per photo. Format: number|caption text

1|First performance in 1993
2|Performing Aradhanai every year
3|Unforgettable moments with Guruji

Lines without a matching photo are ignored. Photos without a matching line show no caption.
📖
readmore.txt
Rule: exact filename readmore.txt
Line 1 = Panel title (e.g. Guru Parambara — The Sacred Lineage)

Remaining lines = Body text. A blank line starts a new paragraph.

No special formatting needed — plain text only.
🎵
Music file
Rule: any filename, must be .mp3 or .m4a
Filename doesn't matter — detected automatically by MIME type (audio/mpeg, audio/mp4).

Only one audio file per folder. Music button is hidden if no audio file is present — no configuration needed.
How captions and music are rendered
Captions
Step 1 — Fetch & parse
On page load the Drive API lists all files. captions.txt is fetched via ?alt=media&key=… and parsed into a JS object: {"1": "caption…", "2": "caption…"}
Captions
Step 2 — Display on slide change
Each time a slide becomes active, the image filename (e.g. 3.jpg) is stripped of its extension → key 3 → looked up in the captions object → shown in the subtitle bar below the photo. Fades out if no caption found.
Music
Step 1 — Detect & load
The Drive file listing is scanned for any file with mimeType starting with audio/. Its Drive file ID is used to construct a streaming URL: drive/v3/files/FILE_ID?alt=media&key=… — set directly as <audio src>. Music button appears.
Music
Step 2 — Play on tap
Browser autoplay policy blocks audio until user interaction. The tap-to-begin overlay captures the first tap → dismisses overlay → starts music at 50% volume, looping. The ♪ button in the corner toggles play/pause at any time.
